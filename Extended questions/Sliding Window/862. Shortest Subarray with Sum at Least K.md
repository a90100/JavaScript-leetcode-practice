# 862. Shortest Subarray with Sum at Least K

## 解題程式碼

解法 1.

```javascript
var shortestSubarray = function (nums, k) {
  let sum = 0;
  let res = Infinity;
  const minQueue = new MinPriorityQueue((o) => o.prefixSum);

  for (let i = 0; i < nums.length; i++) {
    sum += nums[i];
    if (sum >= k) res = Math.min(res, i + 1);

    // 找到到 i 位置的最短 window
    while (minQueue.size() && sum - minQueue.front()?.prefixSum >= k) {
      res = Math.min(res, i - minQueue.dequeue()?.endIndex);
    }
    minQueue.enqueue({ prefixSum: sum, endIndex: i });
  }

  return res === Infinity ? -1 : res;
};
```

解法 2.

```javascript
var shortestSubarray = function (nums, k) {
  let sum = 0;
  let res = Infinity;
  const queue = new Deque();

  for (let i = 0; i < nums.length; i++) {
    sum += nums[i];
    if (sum >= k) res = Math.min(res, i + 1);

    // 找到到 i 位置的最短 window
    while (queue.size() && sum - queue.front()?.prefixSum >= k) {
      res = Math.min(res, i - queue.popFront()?.endIndex);
    }

    // 維護 Increasing Monotonic Queue
    while (queue.size() && queue.back()?.prefixSum > sum) queue.popBack();

    queue.pushBack({ prefixSum: sum, endIndex: i });
  }

  return res === Infinity ? -1 : res;
};
```

微調解法：Deque 內預設 `{ prefixSum: 0, endIndex: -1 }`。

```javascript
var shortestSubarray = function (nums, k) {
  let sum = 0;
  let res = Infinity;
  const queue = new Deque([{ prefixSum: 0, endIndex: -1 }]);

  for (let i = 0; i < nums.length; i++) {
    sum += nums[i];

    // 找到到 i 位置的最短 window
    while (queue.size() && sum - queue.front()?.prefixSum >= k) {
      res = Math.min(res, i - queue.popFront()?.endIndex);
    }

    // 維護 Increasing Monotonic Queue
    while (queue.size() && queue.back()?.prefixSum > sum) queue.popBack();

    queue.pushBack({ prefixSum: sum, endIndex: i });
  }

  return res === Infinity ? -1 : res;
};
```

## 解題思路、演算法

### 為什麼能想到用 prefixSum、minHeap 解題?

prefixSum 可以用來求區間和，有利於找到區間合符合題目要求的子陣列，

而 minHeap 則是用來維護 prefixSum 的最小值，假設當前到索引 i 時的總和為 n，

那和 minHeap 裡最上面的 prefixSum 相減後大於等於 k 的話，

代表從該 prefixSum 的索引到 i 後一位的區間和大於等於 k，為一組可行的子陣列和。

那為什麼 minHeap 彈出後的 prefixSum 不會再用到? 假設索引 i + 1 時的總和為 m，

那不論 m 減掉 prefixSum 是否大於等於 k，組成的子陣列長一定會比第四行提到的子陣列長，

所以可以確定的是 minHeap 彈出後的 prefixSum 不會再用到。

### 再次優化

因為使用了 minHeap 的彈出和加入元素，時間複雜度為 `O(n * log n)`，

但仔細觀察一個例子會發現，不用每個 prefixSum 都加入 minHeap，

例如若 `nums = [-1, -2, -1, 2, 3], k = 3`，則前綴和可以得到 [-1, -3, -4, -2, 1]，

從索引 3 的前綴和，減掉索引 0、1、2 的前綴和，都可以 >= k，那實際上可以不用操作三次，

而是我們記錄下離當前索引最近的最小前綴和即可，也就是索引 2 的前綴和 -4，這樣就可以減少不必要的操作。

所以維護一個 Increasing Monotonic Deque，裡面只放遞增的前綴和。

## 解法的時間、空間複雜度

時間複雜度: 解法 1. `O(n * log n)`，解法 2. `O(n)`
空間複雜度: 解法 1. `O(n)`，解法 2. `O(n)`
